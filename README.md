# 맛집 블로그 도우미 · macOS V1

Swift + SwiftUI + PhotoKit으로 만든 개인용 앱입니다. macOS 13 이상이 필요합니다.

## 실행

```sh
bash scripts/build-app.sh
open dist/BlogAssistant.app
```

처음 실행한 뒤 **사진 접근 허용**을 누르세요. 실제 권한 확인은 번들된 `.app`으로 실행해야 합니다. `swift run`은 사진 권한 확인용으로 사용하지 마세요.

Xcode에서는 `Package.swift`를 열어 소스를 편집할 수 있습니다. 이 저장소는 Swift Package이며 Xcode 앱 타깃은 아닙니다. 실행 가능한 macOS 앱 번들은 위 스크립트가 생성합니다. 전체 Xcode 없이 Command Line Tools로도 빌드할 수 있습니다.

개인용 로컬 빌드는 기본적으로 ad-hoc 서명합니다. 안정적인 서명 ID가 있다면 `CODE_SIGN_IDENTITY='Apple Development: …' bash scripts/build-app.sh`로 지정하세요. 배포용 공증은 포함하지 않습니다.

## V1 동작

- 버튼으로 PhotoKit 접근 권한 요청
- 시스템 사진 보관함의 이미지 중 촬영일 최신순 최대 300장 조회
- 현재 시간대 기준 촬영일별 그룹, 날짜 없는 사진은 마지막 그룹에 표시
- 각 촬영일 안에서 GPS 거리 100m·직전 사진과 시간 간격 90분을 기준으로 방문 후보를 분리합니다. 거리는 그룹의 첫 유효 GPS 좌표를 기준으로 하므로 이동 경로가 연쇄적으로 한 장소에 합쳐지지 않습니다.
- GPS 없는 사진은 현재 시간상 인접한 후보에 포함하고 위치 불확실 수를 표시합니다. GPS가 전혀 없는 후보는 위치 미확인으로 표시합니다. 날짜 없는 사진은 방문을 추정하지 않습니다.
- 후보는 날짜 및 방문 시간 최신순, 후보 내부 사진은 시간순입니다. 음식점 이름 자동 추론은 아직 포함하지 않습니다.
- 방문 카드 또는 상세 보기 버튼을 클릭하면 방문 상세 화면에서 사진을 확인하고 음식점명을 입력·저장할 수 있습니다. 빈 이름 저장은 이름 해제입니다.
- 상단에서 **미정리 / 정리 완료 / 전체** 목록을 전환할 수 있습니다. 기본 화면은 미정리입니다. 방문의 모든 사진에 동일한 음식점명이 저장되면 정리 완료에 표시됩니다. 이름 충돌이나 새로 합쳐진 이름 없는 사진은 미정리에 남으며, 상세 화면에서 이름을 저장해 확정할 수 있습니다. 분류는 현재 조회된 최근 300장 기준입니다.
- 음식점명은 앱의 로컬 UserDefaults에 사진 식별자별로 저장되어 재실행 후에도 유지됩니다. 최근 300장 범위가 바뀌어도 기존 사진이 남아 있으면 이름을 확인할 수 있습니다. 자동 그룹 재계산으로 서로 다른 이름의 사진이 합쳐지면 이름 충돌 안내를 표시합니다.
- 상세 화면의 사진 선택 체크박스로 일부 사진을 고른 뒤 **새 방문으로 분리**할 수 있습니다. 선택 사진을 같은 날짜의 다른 방문으로 이동하거나 방문 전체를 병합할 수도 있습니다.
- 그룹 변경은 로컬에 바로 저장되며 새로고침·재실행 후 유지됩니다. 음식점명은 사진에 연결되어 함께 유지되고, 병합한 그룹의 이름이 다르면 충돌 안내를 확인한 뒤 새 이름을 저장할 수 있습니다.
- **이 날짜 자동 분류로 복원**은 현재 조회된 해당 날짜 사진의 수동 그룹 지정을 해제합니다. 음식점명은 유지합니다. 수정 범위는 조회된 최근 300장으로 제한하며, 새로 들어온 사진은 먼저 자동 그룹으로 표시합니다. 사진 앱의 원본 및 앨범은 수정하지 않습니다.
- SwiftUI `LazyVGrid`로 정사각형 썸네일과 촬영 시간 표시
- iCloud 사진은 필요할 때 썸네일 다운로드, 실패 시 다시 시도
- 사진 보관함 변경 및 앱 재활성화 시 새로고침
- 권한 거부, 기기 정책 제한, 빈 보관함 상태 표시

PhotoKit의 `.readWrite` 접근 레벨을 요청하지만 V1에는 사진 수정·삭제 API 호출이 없습니다. 선택한 사진은 사용자가 지정한 폴더에 JPEG로 내보낼 수 있습니다. 네이버 편집기에 자동 입력·게시하는 기능은 포함하지 않습니다.

사진 앱 → 설정 → 일반에서 **시스템 사진 보관함** 설정을 확인하세요. 권한 거부 후에는 시스템 설정 → 개인정보 보호 및 보안 → 사진에서 앱 접근을 허용하고 돌아오세요.

## 방문 정리 방법

1. **미정리** 목록에서 방문 카드의 **상세 보기**를 엽니다.
2. 잘못 묶인 사진은 체크박스로 선택해 **새 방문으로 분리**합니다. 같은 날짜의 다른 방문을 선택하면 **선택 사진 이동** 또는 **방문 전체 병합**도 가능합니다.
3. 음식점명을 입력하고 **저장**하면 해당 방문이 **정리 완료** 목록으로 이동합니다. 각 목록의 괄호 숫자는 방문 개수입니다.
4. 정리 완료 방문도 상세 화면에서 이름과 그룹을 수정할 수 있습니다. 빈 이름을 저장하면 다시 미정리로 이동합니다.

이름이 서로 다른 방문을 병합하거나 이름 없는 사진이 합쳐졌다면 음식점명을 확인하고 다시 저장하세요. 모든 사진에 동일한 이름이 저장되어야 정리 완료로 분류됩니다. 이 상태는 사진과 음식점명을 정리했다는 의미이며, 블로그 글 작성 완료를 뜻하지 않습니다.

음식점명을 편집 중이라면 먼저 저장한 뒤 그룹을 수정하세요. 그룹 수정은 즉시 저장됩니다. **이 날짜 자동 분류로 복원**을 선택하면 해당 날짜의 현재 조회된 사진들을 GPS·시간 기준으로 다시 분류하며 저장된 음식점명은 유지합니다.

## 후기 작성 준비

1. **정리 완료** 목록에서 방문의 **후기 작성 준비** 버튼을 누릅니다.
2. 음식점명은 저장한 이름, 방문일은 사진 촬영일을 사용합니다. 방문일은 수정할 수 있고 촬영일이 없는 사진은 직접 날짜를 지정합니다.
3. **네이버에서 검색**을 누르면 기본 브라우저에서 해당 음식점의 영업시간을 검색합니다. 확인한 영업시간·휴무·브레이크타임·라스트오더를 **영업정보** 칸에 자유롭게 붙여넣습니다. 웨이팅·예약 메모도 입력할 수 있습니다.
4. **메뉴 추가**로 먹은 메뉴를 여러 개 등록하고 메뉴명·가격·실제 감상을 입력합니다. 방문 사진을 옆에서 보면서 작성할 수 있습니다. 메뉴는 삭제하거나 나중에 추가할 수 있습니다.
5. **저장** 또는 `⌘S`로 중간 내용을 저장합니다. 닫을 때 저장하지 않은 변경이 있으면 저장·버리기·계속 편집을 선택할 수 있습니다. 재실행 후 같은 방문에서 이어서 작성합니다.

목록에는 **후기 정보 미입력 / 입력 중 / 초안 생성 가능** 상태가 표시됩니다. 방문일과 최소 한 개 메뉴의 이름·감상이 필요하며, 추가한 모든 메뉴의 이름·감상이 채워져야 초안 생성 가능 상태입니다. 가격·영업정보·웨이팅 메모는 선택 사항입니다. 정보를 저장한 뒤 **블로그 초안**을 열어 사진을 준비하고 ChatGPT용 작성 요청을 복사할 수 있습니다. 사진 자동 선별·네이버 글 입력은 아직 구현하지 않았습니다.

후기 정보는 로컬 UserDefaults에 JSON으로 저장하며 사진 식별자로 방문에 연결합니다. 사진 그룹이나 음식점명이 바뀌면 기존 입력을 확인하고 다시 저장해야 합니다. 여러 후기 정보가 병합된 경우 하나를 가져오거나 새로 작성할 수 있고, 저장 시 해당 방문의 기존 입력이 현재 내용으로 대체됩니다. 별도 방문의 정보는 유지됩니다. 데이터 읽기에 실패하면 기존 정보가 덮어써지지 않도록 저장을 중단합니다.

## Chrome에서 참고 글 가져오기

`chrome-extension` 폴더에 **맛집 블로그 참고 글 수집** 확장 프로그램을 추가했습니다. 설치·사용 방법은 [확장 프로그램 README](chrome-extension/README.md)를 참고하세요.

확장 프로그램의 **최근 글 가져오기 → 결과 복사**, 앱의 **참고 글 관리 → 참고 글 붙여넣기 → 확인 후 저장** 순서로 사용합니다. 제목·게시일·본문과 `[사진]` 위치를 최신순 최대 5개 가져오며, 앱에서는 형식을 검증하고 미리보기 후 저장합니다. 원문 링크로 실제 글을 확인할 수 있습니다.

참고 글은 방문 후기와 별도로 앱 전용 Application Support 아래 `BlogAssistant/references.json`에 저장합니다. Sandbox 앱이므로 실제 저장 위치는 앱 컨테이너 안입니다. 교체 직전 자료는 같은 폴더의 `references.previous.json`에 백업합니다. 다른 일반 클립보드 텍스트·잘못된 버전·URL·날짜는 저장하지 않습니다.

## ChatGPT로 초안 작성과 사진 배치

1. 정리 완료 방문의 **후기 작성 준비**에서 방문일·메뉴명·감상을 입력하고 저장한 뒤 **블로그 초안**을 엽니다.
2. 왼쪽 사진의 **추가**를 누르면 사진을 보며 `가게 전경`, `돈코츠 라멘`, `기본 반찬`처럼 설명을 직접 입력하는 창이 열립니다. 설명을 입력하고 **사진 추가**를 누릅니다. 취소하면 선택되지 않습니다. 추가 후에도 설명을 수정하고 ↑·↓로 순서를 바꿀 수 있습니다. 설명이 빈 사진은 작성 요청 복사 전에 입력 안내를 표시합니다. 선택 순서가 사진 번호가 되며 사진 구성은 자동 저장합니다.
3. 참고 글 문체 사용 여부와 작성 요청 내용을 확인한 뒤 **작성 요청 복사**를 누릅니다. **ChatGPT 열기**로 이동해 붙여넣고 글 생성을 요청합니다. 사진 파일은 복사되지 않습니다. 사진을 AI에게 보여주고 싶으면 별도로 첨부하세요.
4. ChatGPT가 작성한 결과를 복사하고 앱에서 **초안 붙여넣기**를 누릅니다. 기존 글이 있으면 저장 후 가져오기 또는 현재 수정 버리고 가져오기를 선택합니다. 가져온 글은 확인 후 **초안 저장**을 눌러야 보관됩니다.
5. **사진 미리보기**에서 별도 줄의 `[사진 1]`, `[사진 2]` 표시를 실제 사진으로 확인합니다. 잘못된 번호·누락·중복을 안내하며, 편집 보기에서 글과 표시를 수정할 수 있습니다. 미리보기는 편집기 화면이며 네이버의 실제 게시 레이아웃과 같지는 않습니다.
6. **네이버용 사진 내보내기**에서 저장 폴더를 선택합니다. 새 하위 폴더에 `01_외관.jpg`처럼 번호와 설명이 붙은 사진, `사진순서.txt`가 생성됩니다. **초안 복사** 후 네이버 편집기에 붙여넣고 표시 위치에 해당 사진을 직접 업로드·표시를 제거하세요.

앱에서 직접 AI API를 호출하는 기능과 API 키 설정 화면은 제거했습니다. 기존 ChatGPT 계정에서 직접 글을 생성하므로 앱에 API 키나 별도의 API 결제 설정이 필요하지 않습니다. ChatGPT의 사용 가능 범위는 사용자의 요금제와 현재 한도에 따릅니다. 앱은 작성 요청 복사·ChatGPT 링크 열기만 제공하며 자동 전송하지 않습니다.

사진을 다시 선택하거나 순서를 바꿔도 기존 초안의 번호 연결은 바뀌지 않습니다. **작성 요청 복사** 때 사진 목록·설명·방문 정보·참고 글 ID를 고정하고, 붙여넣은 초안에 그 목록을 연결합니다. 새 사진 구성을 반영하려면 작성 요청을 다시 복사하고 ChatGPT에서 새 결과를 생성해 가져오세요. 기존 API 초안도 읽을 수 있습니다. 기존 초안에 사진 연결이 없거나 현재 선택 순서를 적용하려면 **현재 선택한 사진을 초안에 연결**을 누르세요. 본문의 사진 1부터 현재 선택 순서로 연결하며 글은 유지합니다. 미리보기 확인 후 **초안 저장**을 누르면 연결 정보도 저장됩니다.

초안은 앱 컨테이너 Application Support의 `BlogAssistant/drafts.json`, 사진 구성과 마지막 복사 시점 자료는 `photo-plans.json`에 저장합니다. 초안 교체 전에 저장한 버전은 `drafts.json`에 남고, 저장 직전 파일은 `drafts.previous.json`에 백업합니다. 현재 화면에서는 해당 후기의 가장 최근 초안을 불러옵니다. 그룹 변경으로 새 후기 ID가 만들어지면 기존 초안이 자동 연결되지는 않습니다. 손상된 저장 파일은 덮어쓰지 않습니다.

내보내는 JPEG는 편집된 현재 사진을 기반으로 긴 변 최대 3,000px, 품질 90%로 변환하며 GPS 등 원본 EXIF 메타데이터를 복사하지 않습니다. 원본 Photos 사진은 수정하지 않습니다. iCloud 사진은 다운로드가 필요할 수 있고 사진 권한이 없거나 파일을 읽지 못하면 내보내기를 중단합니다. 기존 파일을 덮어쓰지 않으며 실패한 새 내보내기 폴더는 정리합니다.

참고 글은 말투·문단·사진 설명 방식에만 사용하고, 이번 방문의 사실은 입력한 정보를 따르도록 요청합니다. AI가 이를 항상 지킨다는 보장은 없으므로 게시 전 사실과 감상을 검토하세요.

## 앱에서 네이버 임시저장 · 버튼 한 번

처음 한 번만 연결합니다.

1. `chrome://extensions`에서 이 확장 프로그램을 새로고침하고 추가 권한을 허용합니다. 0.3.8은 네이버 편집기 제어용 `debugger`, 작업 확인용 `alarms`와 앱 연결용 `http://127.0.0.1/*` 접근을 사용합니다.
2. 확장 프로그램 화면의 **앱 연결 코드 복사 · 처음 한 번**을 누릅니다.
3. Swift 앱 상단의 **Chrome 연결**에 코드를 붙여넣고 **연결 저장**을 누릅니다. 연결 준비 완료를 확인합니다. 네이버에 로그인된 Chrome 프로필에서 연결하세요.

이후에는 초안과 사진 연결을 저장하고 **네이버 임시저장**을 누르면 됩니다. 파일 선택·직접 내보내기는 필요하지 않습니다. 앱이 사진을 내부 임시 폴더에 준비하고 Chrome 확장 프로그램에 글·사진을 전달합니다. 확장 프로그램이 새 글쓰기 탭에서 제목·본문·사진을 입력하고 검증 후 저장합니다. 결과는 앱 화면에 표시합니다. 발행은 직접 진행합니다.

대상은 `bluedog129`의 맛집탐방(65)입니다. 첫 줄은 제목, 이후는 본문입니다. 사진 번호의 누락·중복·범위 오류와 미저장 수정이 있으면 전송 버튼을 사용할 수 없습니다. 편집기 제목·본문의 단어와 사진 위치·개수 검증을 통과한 경우에만 **저장**을 누릅니다. 저장 완료 알림 또는 임시저장 개수 변경을 확인하지 못하면 성공으로 표시하지 않습니다. 작업 중 편집기 탭을 수동으로 편집하지 마세요.

앱 연결은 `127.0.0.1:48765`에서만 수신하며 연결한 확장 프로그램의 ID·무작위 연결 토큰을 확인합니다. 외부 네트워크에서 수신하지 않습니다. 사진은 파일 경로 대신 현재 작업에 등록된 사진 번호로만 전달합니다. 작업은 한 번만 받을 수 있어 확장 프로그램 탭 새로고침이나 중복 버튼으로 같은 요청을 다시 입력하지 않습니다. 연결 코드는 다른 사람에게 공유하지 마세요. 앱의 **Chrome 연결 → 연결 해제**에서 연결을 끊을 수 있습니다.

앱이 만든 임시 사진 폴더는 작업 결과가 돌아오거나 시간 초과 시 정리합니다. 앱 종료 등으로 결과를 못 받으면 다음 실행에서 확인되지 않은 작업을 안내합니다. 실패한 네이버 탭과 일부 업로드·자동저장 자료는 남을 수 있으므로 재시도 전 임시저장 목록을 확인하세요. 작업 수신은 90초, 결과 확인은 최대 20분 대기합니다. 포트 충돌·다른 Chrome 프로필·확장 프로그램 권한 거부·편집기 변경·접근 제한은 오류를 표시하며 자동 재시도하지 않습니다.

Swift 내보내기·로컬 연결 실제 통신, 인증·중복 방지·사진 전달·결과 반환·임시 파일 정리 테스트와 확장 프로그램의 모의 편집기 자동 처리 테스트를 통과했습니다. 2026-10-07 사용자가 실제 네이버에서 글·사진 입력과 임시저장 완료를 확인했습니다. 이후 0.3.8에서 OS 사진 선택창이 남는 문제를 보완했으며 사용자가 완료를 확인했습니다. 네이버 편집기 변경에 따른 호환성은 지속 확인이 필요합니다.

## 수동 확인

1. `.app`을 실행하고 권한 요청 전 안내 화면을 확인합니다.
2. 접근을 허용하고 최신 촬영일 순서, 날짜 그룹 및 썸네일을 확인합니다.
3. 앱 권한을 끈 뒤 돌아와 사진이 사라지고 설정 안내가 표시되는지 확인합니다.
4. 사진을 추가·삭제하고 목록이 갱신되는지 확인합니다.
5. iCloud 사진 및 네트워크 연결 실패 시 썸네일 재시도를 확인합니다.
6. 같은 날 다른 장소, 90분 넘게 간격이 벌어진 재방문 및 GPS 없는 사진의 후보 표시를 확인합니다.
7. 방문 상세에서 일부 사진을 분리하고 다른 방문으로 이동·병합한 뒤 새로고침 및 앱 재실행으로 그룹이 유지되는지 확인합니다.
8. 다른 음식점명을 가진 방문들을 병합하면 이름 충돌 안내가 표시되는지, 자동 분류 복원 후에도 음식점명이 유지되는지 확인합니다.
9. 음식점명 저장 후 미정리 목록에서 사라지고 정리 완료 목록에 표시되는지, 이름 해제·충돌·이름 없는 사진 병합 시 미정리로 돌아오는지 확인합니다.
10. 정리 완료 방문에서 후기 준비를 열고 식당 정보·메뉴 두 개를 입력·저장합니다. 앱 재실행 후 입력 내용과 준비 상태를 확인합니다.
11. 메뉴 감상이 빠지면 입력 중으로 표시되는지, 닫을 때 미저장 변경 안내 및 저장 후 닫기가 동작하는지 확인합니다.
12. 후기 정보를 입력한 방문들을 병합·분리한 뒤 기존 정보 확인 안내와 재저장을 확인합니다.
13. 참고 글을 붙여넣고 앱 재실행 후 저장 유지와 원문 링크를 확인합니다.
14. 블로그 초안에서 사진 선택·설명·순서를 저장하고 작성 요청을 복사합니다. ChatGPT 결과를 가져와 사진 미리보기·누락 및 잘못된 번호 안내를 확인합니다. 앱 재실행 후 사진 구성과 저장된 초안이 유지되는지 확인합니다.
15. 작성 요청을 복사한 후 사진 순서를 바꿔도 기존 초안의 연결이 유지되는지 확인합니다. 초안 교체 전 저장, 미저장 변경 닫기 안내를 확인합니다.
16. 사진을 내보내 JPEG의 번호·방향·이미지 품질·메타데이터와 사진순서.txt를 확인합니다. 사진 권한 해제·삭제·iCloud 다운로드 실패 시 안내를 확인합니다.

그룹화 및 저장 로직 테스트: `bash scripts/test-grouping.sh` (거리·시간 경계, GPS·날짜 누락, 음식점명 저장, 수동 분리·이동·병합, 사진 보존, 재로드 및 복원, 후기 정보 준비 상태·저장·방문 변경·손상 데이터 처리). XCTest 없이 Command Line Tools로 실행합니다.

초안 자동 검증은 API 키나 과금 없이 실행합니다. 프롬프트의 사실 자료·사진 식별자 제외, 사진 표시의 해석·오류 안내, 복사 시점 사진 순서 고정·저장, 기존 초안 호환성·이전 버전 보존·손상 파일 보호를 확인합니다. 실제 Photos 라이브러리, ChatGPT 복사·붙여넣기, JPEG 내보내기를 포함한 화면 흐름은 수동 확인 항목입니다.

현재는 사진 조회, 방문 그룹 수정, 식당·메뉴 정보 입력, Chrome 참고 글 수집, 사진 선택·순서·설명, ChatGPT 작성 요청 복사, 초안 가져오기·편집·저장·사진 미리보기·사진 내보내기까지 구현했습니다. 네이버 편집기에 글·사진 입력과 임시저장 자동화는 최초 연결 후 실제 편집기 검증이 필요하며, 발행은 직접 진행합니다.

Chrome 실행 시 일반 HTTPS 주소를 열고, 확장 프로그램이 인증된 `/pending` 요청으로 작업을 확인해 자체적으로 처리 화면을 엽니다. `alarms` 권한으로 최대 30초 간격으로 대기 작업을 확인합니다. macOS에서 `chrome-extension://` 주소를 직접 여는 방식은 사용하지 않습니다.

## 메뉴와 사진 함께 입력

후기 작성 준비의 각 메뉴에서 **메뉴 사진**을 펼쳐 여러 사진을 선택할 수 있습니다. 사진 선택은 선택 사항이며 메뉴명·가격·감상과 함께 저장됩니다. 같은 사진을 여러 메뉴에 연결할 수도 있습니다.

처음 블로그 초안을 열면 연결한 메뉴 사진이 자동으로 추가되고 메뉴명이 사진 설명에 입력됩니다. 같은 사진은 한 번만 추가하며 연결한 메뉴명을 함께 표시합니다. 기존 사진 구성은 유지하며, 이후 연결한 사진은 **메뉴 사진 추가**로 추가하세요. 기존 사진 설명과 순서는 덮어쓰지 않습니다. 메뉴명을 바꾼 뒤 기존 초안 사진 설명도 바꾸려면 해당 설명을 직접 수정하세요. 전경·반찬 등은 초안 화면에서 별도로 추가할 수 있습니다.
