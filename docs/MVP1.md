# MVP1 — 개인용 네이버 맛집 블로그 작성 도우미

기준일: 2026-10-07. macOS Swift + SwiftUI + PhotoKit 앱과 Chrome 확장 프로그램 0.3.8을 기준으로 합니다. 실제 네이버 임시저장 완료는 사용자가 확인했습니다. 공개 발행은 사용자가 직접 합니다.

## 구현 범위

- Photos 권한 요청, 최근 사진 300장 조회, 촬영일별 썸네일 그리드 및 라이브러리 변경 반영.
- 날짜·위치·시간을 이용한 방문 그룹: 기본 위치 거리 100m, 시간 간격 90분. 위치 없는 사진도 처리합니다.
- 방문 그룹 수동 분할·이동·병합, 식당 이름 저장, 미정리/정리 완료/전체 필터.
- 방문일, 영업시간, 브레이크타임, 휴무·라스트오더, 웨이팅 메모 입력. 여러 메뉴의 이름·가격·감상 입력.
- Chrome에서 본인 블로그 맛집 카테고리 최근 글 최대 5개 수집, JSON 클립보드 가져오기. 말투·문단·사진 설명 참고용입니다.
- 초안용 사진 선택·제외·순서 변경 및 사진 설명 직접 입력. 메뉴명 등 자유 텍스트를 사용합니다.
- 방문 정보·메뉴·참고 글·사진 번호와 설명을 담은 ChatGPT 작성 요청 복사. ChatGPT에서 직접 생성하고 앱에 붙여넣습니다.
- 초안 편집·저장·사진 미리보기, 독립된 줄의 `[사진 1]` 표시와 실제 사진 연결. 번호 누락·중복·범위 오류 검사.
- 작성 요청 복사 당시 사진 구성을 고정해 초안에 연결. 기존 초안은 ‘현재 선택한 사진을 초안에 연결’로 다시 연결할 수 있습니다.
- 앱 버튼으로 Chrome 새 글쓰기 화면에 제목·본문·사진을 입력하고 원문 검사 후 임시저장. 앱에 진행·성공·실패 상태 반환.
- 수동 사진 내보내기 및 JSON/JPEG 파일 선택 전달은 보조 경로로 유지합니다.

식당 정보 자동 검색은 MVP1에서 제외했습니다. 사용자가 확인해 입력합니다. OpenAI API 직접 호출은 ChatGPT 구독과 API 결제가 별개라는 점을 고려해 수동 ChatGPT 흐름으로 전환했습니다. 현재 앱에 API 키나 API 결제는 필요하지 않습니다. 사진 파일은 ChatGPT 작성 요청에 포함되지 않고 설명만 전달됩니다.

## 전체 사용 순서

1. 앱을 실행해 Photos 접근을 허용합니다. 방문 그룹을 정리하고 식당 이름을 저장합니다.
2. 식당 방문 정보와 먹은 메뉴를 입력합니다.
3. 필요하면 Chrome 확장 프로그램으로 참고 글을 수집해 앱에 가져옵니다. 대상은 `bluedog129`, 맛집탐방 카테고리 65입니다.
4. 초안 창에서 사진을 추가하고 각 사진 설명을 입력합니다. 순서가 사진 번호입니다.
5. 작성 요청을 복사해 ChatGPT에 붙여넣고 생성 결과를 앱에 붙여넣습니다.
6. 사진 미리보기에서 배치와 글을 확인하고 초안을 저장합니다. 이전 사진 구성 경고가 있으면 현재 사진 연결을 다시 저장합니다.
7. 최초 한 번 Chrome 확장 프로그램의 ‘앱 연결 코드 복사’를 누르고 앱 메인 화면 상단 ‘Chrome 연결’에 전체 코드를 붙여넣어 저장합니다. 초안 창이 열려 있으면 닫아 메인 화면으로 돌아갑니다. 확장 프로그램 ID만 입력하는 방식은 아닙니다.
8. 확장 프로그램 ‘앱 연결 상태 확인’에서 연결 상태를 확인합니다.
9. 앱 ‘네이버 임시저장’을 누릅니다. 진행 중 편집기 조작이나 탭 변경을 피합니다. 이전 작성 글 안내가 뜨면 기존 내용을 보관할지 판단하고 직접 처리합니다.
10. 앱의 임시저장 완료 표시와 네이버 임시저장 목록을 확인합니다. 발행 전 사실·감상·사진·카테고리를 검토하고 직접 발행합니다.

## 저장과 전달 구조

- 식당 이름, 방문 그룹 편집, 방문 리뷰 정보: 앱 UserDefaults. 방문 리뷰 키는 `visitReviews.v1`입니다.
- 참고 글: 앱 Application Support의 `BlogAssistant/references.json`.
- 초안과 이력: `drafts.json`. 사진 선택 계획: `photo-plans.json`. 앱 샌드박스 사용 시 앱 컨테이너 안에 저장됩니다. JSON 파일은 이전 파일 백업을 유지합니다.
- 사진 원본은 Photos에 유지합니다. 전달용 JPEG는 긴 변 최대 3,000px, 품질 90%, 현재 편집본 기준으로 만들며 원본 GPS/EXIF를 복사하지 않습니다.
- 전달 패킷은 `naver-post.json`: 첫 비어 있지 않은 줄이 제목(최대 200자), 이후 본문 및 사진 블록. 본문 내용과 사진 표시를 검사합니다.
- 앱은 `127.0.0.1:48765`에만 서버를 엽니다. 확장 프로그램 ID·무작위 토큰으로 인증하며 사진은 현재 작업의 번호로만 요청할 수 있습니다.
- 연결 설정은 `naverBridge.v1`, 미완료 표시 여부는 `naverBridge.pending`에 저장합니다. 코드는 다른 사람에게 공유하지 않습니다.
- 앱은 일반 HTTPS 블로그 주소로 Chrome을 실행합니다. 확장 프로그램이 `/pending`을 인증 조회해 자체 작업 화면을 엽니다. 작업 확인 간격은 최대 30초입니다.
- 작업 수신 대기 90초, 전체 결과 확인 최대 20분. 작업은 한 번만 수신하며 자동 재시도하지 않습니다. 완료·실패·시간 초과 시 앱 임시 사진 폴더를 정리합니다.
- 확장 프로그램 권한: scripting, storage, clipboardWrite, debugger, alarms 및 네이버/loopback 접근. debugger로 편집기에 키·마우스 입력을 전달합니다. 네이버 로그인은 동일 Chrome 프로필에 있어야 합니다.

## 예외 처리와 해결 기록

| 현상 | 처리 |
| --- | --- |
| macOS가 Chrome 확장 주소를 열 수 없음 | 앱의 직접 `chrome-extension://` 실행을 제거하고 일반 HTTPS 실행 + 확장 프로그램 작업 조회로 변경 |
| 확장 프로그램이 작업을 받지 못함 | 연결 상태 확인 버튼 추가. 403이면 전체 연결 코드를 다시 복사해 앱에 저장 |
| 기존 사진 구성이 없는 초안 | 현재 선택 사진 연결 버튼으로 명시적 재연결 후 저장 |
| 두 번째 사진 선택 입력창을 찾지 못함 | 좌표 대신 사진 버튼 요소를 직접 클릭 |
| 제목 입력 확인 실패 | 탭 활성화, 즉시 스크롤, 위치 재조회 및 포커스 대기 추가 |
| 줄바꿈 소실·이모지 뒤 본문 누락 | 줄 단위 입력과 Enter 키 처리, 보충 평면 문자 분리 입력 |
| 제목 일부가 본문에 섞임 | 제목 입력 완료 후 Enter로 본문 전환 |
| 이전 작성 글 복구 안내 | 감지된 안내는 최대 3분 대기. 사용자가 직접 처리. 기존 글이 열리면 덮어쓰지 않고 중단 |
| 원문 검사 불일치 | 저장 중단, 다른 구간 번호 안내. 검사를 느슨하게 하지 않음 |
| 사진마다 OS 파일 선택창이 남음 | CDP 선택창 가로채기 + 자동 업로드 중 파일 input 클릭 기본 동작 취소, 종료 시 취소 처리 해제 |
| 앱 종료·결과 미확인 | 다음 실행에서 결과 불명 안내. 네이버에서 먼저 확인 후 재시도 |

업데이트는 `chrome://extensions`에서 새로고침합니다. 기존 수집 화면은 닫고 다시 열어야 새 스크립트가 적용됩니다. 새로고침만 했다면 연결 ID·토큰은 유지됩니다. 연결 코드 불일치 안내가 있을 때만 다시 연결합니다. 실패 탭이나 네이버 자동저장 자료는 남을 수 있으므로 중복 여부를 확인합니다. 이미 임시저장된 글을 같은 문제 확인 목적으로 다시 생성할 필요는 없습니다.

## 검증

Swift 검사는 `bash scripts/test-grouping.sh`, 앱 빌드는 `bash scripts/build-app.sh`입니다. 전체 Xcode 없이 Swift CLI로 빌드하고 앱 번들을 서명합니다. 실제 Photos 권한 확인은 `.app`에서 진행합니다.

확장 프로그램 검사는 다음 명령을 사용합니다.

```sh
node Tests/extension-checks.mjs
node Tests/posting-checks.mjs
node Tests/background-checks.mjs
node Tests/bridge-extension-checks.mjs
node Tests/text-input-checks.mjs
node Tests/photo-picker-checks.mjs
```

일부 검사는 jsdom이 필요합니다. `EXTENSION_TEST_JSDOM`으로 설치된 jsdom 경로를 지정할 수 있으며 기본 테스트 경로는 `/tmp/blog-assistant-extension-check/node_modules/jsdom`입니다. 운영 앱 의존성은 아닙니다.

검증 범위: 방문 그룹·저장·초안·사진 표시 검사, 실제 loopback 통신과 인증/CORS/중복 수신 거부/사진 전달/결과 반환/임시 파일 정리, 확장 프로그램 모의 입력 흐름과 이전 글 안내 대기, 여러 줄·이모지 입력 보존, 반복 파일 선택 기본 동작 취소 및 복구.

2026-10-07 사용자는 실제 네이버 글·사진 입력 및 임시저장 완료를 확인했습니다. 이어서 파일 선택창 보완 후 완료를 확인했습니다. 모의 테스트만으로 모든 네이버/Chrome/macOS 조합을 보장하지는 않습니다.

## MVP1 제한과 다음 후보

네이버 SmartEditor DOM 변경, 로그인 만료, 권한 거부, 다른 Chrome 프로필, 포트 충돌 및 iCloud 사진 다운로드 실패에 영향을 받습니다. 사진 검사는 삽입 순서·개수·배치 기준이며 이미지 픽셀 동일성을 검사하지 않습니다. 복구 안내 감지는 현재 알려진 문구·DOM 기준이고 새로운 팝업은 추가 대응이 필요합니다. 대상 블로그·카테고리는 현재 개인 계정 기준으로 고정되어 있습니다.

후속 후보는 대상 블로그 설정화, 편집기 호환성/안내 개선, 중단 작업 재개, 글쓰기 입력 안정성 강화입니다. 공개 발행 자동화나 식당 정보 자동 검색은 아직 구현 범위에 포함하지 않습니다.
