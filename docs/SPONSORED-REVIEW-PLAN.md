- **경험 구역:** 본문은 기존 왼쪽 정렬과 짧은 문단을 유지한다. 사진 → 구체적인 감상 → 다음 사진의 흐름을 사용하며 메뉴명·가격·감상의 시각적 위계를 통일한다. 소제목을 모든 사진마다 붙이지 않는다.
- **개인 색깔:** 기존 글꼴·담백한 문체를 바탕으로 소제목과 구분선을 통일한다. 사용자 선호에 따라 메뉴명·소제목의 남색 구분을 없애고 본문과 같은 색에 글자 크기·볼드로 위계를 표현한다. 아이콘은 정보 구역의 보조 표식으로 제한하는 안을 제안한다. 인용 장식·중앙 정렬·이모지의 구체적인 조합은 아직 확정하지 않았다.
- **지도(사용자 확정 요구):** 블로그 본문에서 지도·위치 핀·가게명·주소를 바로 볼 수 있도록 한다. 첨부 화면과 같은 네이버 장소 지도 블록을 정보 구역에 삽입하는 방향으로 구현한다. 현재 `[네이버지도]`의 텍스트 링크 표시만으로는 이 요구를 충족하지 않는다. 실제 편집기 삽입·전송·검증 경로는 구현 전 확인한다.

### 본문에 바로 보이는 장소 지도

- 권장 배치: 짧은 도입 → ‘방문 전 확인’ 소제목 → 장소 지도 → 영업시간·주차·교통 등 요약 → 경험·메뉴 기록. 지도 아래 표시되는 가게명·주소를 다른 정보 줄에서 불필요하게 반복하지 않는다.
- 독자는 별도 링크를 열기 전에 본문 안에서 가게 위치와 주변 역·도로를 확인할 수 있어야 한다. 장소 블록은 해당 매장의 네이버 장소로 연결한다. 예약 버튼은 해당 장소·네이버 편집기가 제공하는 경우에 표시하며 앱이 임의로 만들지 않는다.
- 매장명만으로 같은 이름의 다른 지점을 자동 선택하지 않는다. 저장한 지도 링크와 장소명·주소를 대조하고 대상 장소를 확인하는 단계를 마련한다. 이미지 예시에 있는 약산옥을 다른 방문의 기본값으로 저장하지 않는다.
- 네이버 전달 자료에는 지도 위치를 독립된 블록으로 표현하는 안을 사용한다. 사진·영상 번호와 순서는 유지하고 지도 앞뒤 본문이 이어지는지 검증한다. 기존 지도 링크를 가진 초안은 실제 장소를 확인한 후 새 지도 블록으로 변환한다.
- 앱 미리보기에서도 지도 삽입 위치와 대상 장소를 확인할 수 있게 한다. 지도 자체의 표시 방법은 기술 검토 후 정하고, 단순 자리 표시자를 실제 지도 미리보기처럼 안내하지 않는다.
- 지도 삽입에 실패하면 완료나 임시저장 성공으로 처리하지 않는다. 오류와 재시도·수동 삽입 경로를 안내한다.
- 완료 기준: 실제 네이버 편집기와 임시저장 초안에서 지도 이미지 영역·위치 핀·정확한 장소명·주소가 보이고, 모바일 폭에서도 레이아웃이 유지된다. 공개 발행 없이 임시저장 상태로 검증한다.

현재 상태는 요구 확정이며 지도 블록 구현·실제 편집기 검증은 아직 진행하지 않았다.

앱 업데이트는 ‘내용 구성’과 ‘지면 서식’을 함께 다룬다. 작성 요청에 경험 중심 구성 규칙을 추가하고, 앱의 미리보기와 네이버 임시저장 결과에 같은 소제목·정보 구역·여백 규칙을 적용한다. 자유 입력 영업정보를 지원하면서 주소·주차·교통·공개 연락처를 선택 입력으로 구조화하는 안을 검토한다. 확정된 방문 정보만 표시한다.

검증 기준: 모바일 폭에서 정보 항목과 메뉴 구역을 쉽게 찾을 수 있는지, 음식·감상에 도달하기까지 정보 구역이 지나치게 길지 않은지, 본인 글과 비교해 말투와 감상의 강도가 유지되는지 확인한다. 앱 미리보기와 실제 네이버 편집기 결과의 서식 일치도 확인한다. 이 구역은 방향 합의용이며 UI 구현은 아직 진행하지 않았다.

## 권장 사용자 흐름

사용자와 합의한 범위는 사진 촬영 이후의 **글 작성 요구사항 체크리스트**다. 예약 완료·촬영 완료 투두나 방문 전 관리 화면은 추가하지 않는다.

1. 사진 선택·메뉴 감상 입력은 기존 흐름을 사용한다.
2. ‘블로그 초안’ 화면에 접을 수 있는 ‘체험단 요구사항’ 구역을 추가한다. GPT가 원문을 정리한 요구사항 결과를 별도로 가져와 확인·수정·저장한다. 원문 출처와 확인 근거도 보존한다.
3. 저장한 조건을 기존 ‘작성 요청 복사’에 포함한다. 앱은 AI를 직접 호출하지 않고 현재 ChatGPT 복사·붙여넣기 흐름을 유지한다.
4. GPT가 생성한 글은 기존 ‘초안 붙여넣기’로 가져온다. 글 초안과 요구사항 데이터는 별도로 저장해 서로 덮어쓰지 않는다.
5. 붙여넣은 글과 실제 본문에 배치된 사진을 대상으로 네 가지를 확인한다: 제목·본문·태그 키워드, 요청 소개·지정 문장·고지, 필수 사진 포함, 사진 수 조건.
6. ‘충족 / 미충족 / 직접 확인 필요’로 결과와 근거를 보여준다. 글·제목·사진·요구사항이 바뀌면 재검사한다. 내용의 의미나 실제 피사체를 확인할 수 없는 항목은 자동 통과시키지 않는다.
7. 사용자가 부족한 항목을 수정·확인하고 기존 초안 저장·네이버 임시저장으로 진행한다.

첫 버전의 요구사항 가져오기는 정해진 형식의 GPT 정리 결과를 검증해 받는다. 파싱 실패·불완전한 필드는 안내하고 기존 저장 조건을 보존한다. 정리 요청 복사와 요구사항 수정 화면도 제공하는 방향이다. PDF 텍스트 추출과 로그인된 메일 URL 자동 읽기는 별도 확장이다. 미확정 조건과 GPT가 추출한 정보는 사용자가 확인하기 전까지 확정 값으로 취급하지 않는다.

## 데이터·작성 규칙

- 방문별 선택 사항인 `campaign`을 `VisitReview`에 추가하는 안. 일반 후기는 `nil`, 기존 저장 자료는 `decodeIfPresent`로 호환한다.
- 원문 출처·수신일·PDF 쪽수, 조건 종류, 필수/선택, 적용 지점, 확인 상태, 확정 값, 사용자 확인 근거를 보존한다.
- 사용자 확인은 원문 후보보다 우선한다. 이번 두 캠페인의 방문시간은 메일 기준, 촬영 기기는 매니저 확인에 따른 휴대폰 허용으로 저장한다. 과거 PDF를 다시 가져와도 이 확정 값을 덮어쓰거나 해결된 항목을 다시 경고하지 않는다.
- 공개 매장 번호와 예약 연락처를 분리한다. 프롬프트에는 작성에 필요한 공개 정보만 포함하고 예약 번호·개인 연락처·기프티콘 수령 정보는 제외한다.
- 제공 예정 메뉴와 실제 주문·시식 메뉴를 분리한다. 업체 제공 메뉴 목록만으로 맛이나 가격을 생성하지 않는다.
- ‘일반 후기/체험단’은 작성 조건이고 ‘기본 텍스트/단정한 기록’은 서식이다. 별도 축으로 유지한다.
- 확정 필수 키워드는 기존 제목 길이 목표와 일반적인 키워드 나열 회피보다 우선한다. 개인 감상 보존·사실 근거 규칙은 유지한다. 과장 요청이 감상과 충돌하면 자동 긍정문 대신 확인 대상으로 표시한다.
- 제목만 다듬는 요청에도 같은 조건을 전달해 필수 키워드가 사라지지 않게 한다.
- 업체 원문은 자료다. 원문에 있는 외부 지시나 연락·전송 요청을 앱 실행 지시로 해석하지 않는다.
- 초안에는 생성 당시 캠페인 조건 스냅샷을 저장한다. 조건 변경 시 재검사 필요를 표시하며 기존 초안을 조용히 바꾸지 않는다.

## 조건 검사

| 검사 | 자동 판정 범위 | 처리 제안 |
| --- | --- | --- |
| 필수 키워드 | 제목·본문·태그를 분리해 확정된 모든/택일 조건 검사 | 미포함 위치와 키워드 표시, 임시저장 전 수정 |
| 지정 문장·고지 | 확정 문장의 포함·선택 위치 확인 | 빠지면 임시저장 전 수정 |
| 필수 사진 포함 | 사용자가 요구사항에 연결한 사진이 실제 초안 본문에 배치됐는지 확인 | 사진 내용은 사용자가 직접 확인. 선택 목록에만 있고 글에 빠졌다면 미충족 |
| 사진 수 | 실제 초안에 배치된 중복 없는 사진 수를 확정된 게시 사진 수 조건과 비교 | 영상은 사진 수에서 제외. 원문의 ‘20컷 촬영’을 ‘20장 게시’로 자동 변환하지 않으며 촬영 수 조건만 있으면 자동 충족 판정 대신 직접 확인 필요로 표시 |
| 소개·감상 조건 | 본문 위치와 사용자 확인을 연결 | 단어가 있다는 이유만으로 의미 충족 처리하지 않음 |
| 미확정·충돌 | 확인 필요 목록 | 초안 작업은 가능, 최종 조건 점검에는 미해결 표시 |
| 일정·예약·촬영 안내 | 원문 참고 정보로 보존 | 작성 요구사항 체크리스트의 완료 검사와 분리하며 예약·촬영 완료 ToDo는 만들지 않음 |
| 일반 후기 | 기존 검사 유지 | 체험단 조건 적용 없음 |

태그는 ‘암사 흑염소’와 `#암사흑염소`를 연결할 수 있으나 본문·제목은 정규화 정책을 별도로 정의한다. 비슷한 지명이나 메뉴명으로 조건이 잘못 충족되지 않게 한다. 현재 네이버 전송은 본문 해시태그와 편집기 태그 등록을 같은 것으로 보장하지 않으므로 첫 버전의 검사 대상은 본문 끝 해시태그다. 별도 태그 입력 지원 여부는 전달 코드를 추가 확인한다.

## 테스트 계획

아래는 전체 업그레이드의 테스트 계획이다. 가이드 가져오기·출처 검증·잘못된 결과 거부·조건 저장·프롬프트 연동·키워드·고지·사진 수·수동 확인 갱신·기존 자료 호환 자동 검사는 수행했다. 샘플 UI에서 원문 저장→정리 결과 확인·저장→사진 연결·직접 확인→초안 수정 시 누락 검사도 확인했다. 실제 두 캠페인 자료를 GPT로 정리하고 네이버 임시저장까지 진행하는 전체 검증과 지도·정보 구역 검증은 남아 있다. 테스트 입력은 가상 예시로 표시한다.

1. 기존 일반 후기·초안 파일을 읽고 저장·재로드해도 내용과 서식이 유지된다.
2. 블랙루머 조건에서 제목 키워드·지정 로스팅 문구·고지를 각각 제거하면 정확한 누락이 표시된다.
3. 약산옥 키워드를 3개 후보로 저장하고 미확정 상태를 유지한다. 사용자가 확정한 조합만 검사하며 제목만 재생성해도 동일 조건을 유지한다.
4. 사용자 확인에 따라 방문시간에 메일 기준을 적용하고 두 캠페인의 휴대폰 촬영을 허용한다. PDF 재입력·앱 재실행 후에도 확정 값과 확인 근거가 유지되며 해결된 시간 출처·촬영 기기 항목을 다시 경고하지 않는다. 과거 일정 등 별도로 미해결인 항목은 확인 필요로 유지한다.
5. 압구정 방문에는 홍대 지점 전용 사진 조건을 요구하지 않는다.
6. 글에 ‘포토존’이 있어도 사진 연결·사용자 확인이 없으면 충족으로 처리하지 않는다. 19장·20장 경계, 동영상·과거 사진·중복 사진을 구분한다.
7. 입력에 없는 맛·가격·재방문 의사·효능을 작성 요청이 요구하지 않는다. 아쉬운 실제 감상을 긍정문으로 바꾸지 않는다.
8. 원문에 예약 휴대전화가 있어도 작성 요청과 공개 글에 자동 포함되지 않는다.
9. 사진→영상→사진 표시와 순서가 유지된다. 초안 생성 뒤 사진이나 조건을 바꾸면 스냅샷 차이를 표시한다.
10. 두 캠페인의 실제 방문 자료로 작성 요청→초안 가져오기→검사→수정→미리보기→네이버 임시저장을 확인한다. 마지막 고지·키워드·사진·서식을 편집기에서 확인하고 테스트 결과를 남긴다.
11. 지도 블록의 장소명·주소와 저장한 대상이 일치하는지 확인한다. 지도 앞뒤 본문과 사진·영상 순서, 동명 지점 구분, 기존 링크 초안 호환, 삽입 실패 시 성공 처리 방지를 검사한다. 실제 편집기·임시저장 초안과 모바일 폭에서 본문 지도가 바로 보이는지 확인한다.

업데이트 범위는 ‘경험 중심 구성 + 정돈된 정보 구역 + 본문 장소 지도’와 ‘캠페인 조건 저장 + 작성/제목 요청 반영 + 초안 누락 검사’로 구성한다. 지면 개선은 기존 양식을 확장하고 실제 네이버 임시저장 결과까지 확인한다.
